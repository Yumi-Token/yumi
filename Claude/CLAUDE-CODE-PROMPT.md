## 1. `docs/DECISIONS.md` — D-019 신규 (맨 위, D-018 위에)

```markdown
## D-019 · 타임락 운영자를 Safe 2-of-3 멀티시그로

**결정** — `TimelockController`의 `proposers`에 개인 지갑(EOA)이 아니라 **Safe 멀티시그(2-of-3) 주소**를 넣는다. Safe 생성을 **배포 순서 0번**으로 올린다. 초기 LP 투입 후 남는 근거리 재고 1M도 Safe로 옮기고 배포 지갑을 비운다.

**이유 ① 단일 키가 예약과 취소를 동시에 독점하는 구조가 위험하다.** D-007의 「알아야 할 것」 참조. 도난이 아니라 **영구 동결**이 일어난다.

**이유 ② 온체인에는 2FA가 없다.** 컨트랙트는 서명만 보므로 본인 확인 수단이 프로토콜에 존재하지 않는다. 멀티시그가 그 구조적 등가물이다.

**이유 ③ 하드웨어 지갑으로는 안 풀린다.** 하드웨어는 키 탈취를 막지만 키 하나가 역할을 독점하는 구조는 그대로다. 그리고 하드웨어는 **잘못된 서명을 막지 못한다** — 가짜 사이트에서 승인을 누르면 기기는 충실히 서명한다.

**구성 (1인 기준)**

| 키 | 위치 | 평소 |
|---|---|---|
| ① | PC 암호화 키스토어 (또는 하드웨어) | 사용 |
| ② | 폰 지갑 앱 — **반드시 다른 기기** | 사용 |
| ③ | 종이·금고 | 복구용, 안 씀 |

**조건: 키가 서로 다른 기기에 있어야 한다.** 3개가 같은 PC에 있으면 보호가 0이다. 기준은 "하드웨어냐"가 아니라 **"독립적이냐"**다.

**Safe는 지갑이 아니라 컨트랙트다.** 키를 보관하지 않고 **주소 목록과 정족수만** 저장한다. 그래서 **Safe 자체에는 시드 문구가 없고, 복구 수단이 곧 서명자 키 3개**다.

**복구 방식** — 키 1개를 잃거나 유출당하면 남은 2개로 `swapOwner`를 실행해 교체한다. 명부 변경 자체가 정족수를 요구하는 Safe 트랜잭션이다.

**한계 — 버티는 건 정확히 「1개까지」다.**

| 유출 | 결과 |
|---|---|
| 1개 | 공격자 1표. 아무것도 못 함. 남은 2표로 제거하면 복구 완료 |
| **2개** | 공격자도 정족수 도달. **먼저 실행하는 쪽이 이김** |

⚠️ **키 2개가 유출되면 7일 예고는 방어가 아니다.** Safe 서명자 명부 변경은 **타임락을 거치지 않고 즉시** 실행되므로, 공격자는 먼저 발행자를 명부에서 지운다. 그 시점부터 발행자는 취소 권한도 없다.

**그래도 공격자가 못 하는 것** — 잠긴 토큰 조기 인출(시간은 못 앞당김), 홀더 토큰 탈취, 추가 발행, 기록 삭제. 베스팅 일정은 어떤 키로도 안 바뀌므로 **65M은 여전히 2년 뒤부터 8년에 걸쳐** 나온다. 한 번에 터는 게 아니라 느린 적하를 물려받는다.

**그리고 7일은 발행자 대신 홀더를 지킨다.** LP 인출에 7일이 걸리므로 그동안 예약이 공개되고 **홀더는 팔고 나갈 수 있다.** 타임락이 발행자를 지키는 데 실패해도 홀더를 지키는 데는 성공한다.

**기각한 것 — 거부권(veto) 키.** Safe 밖의 별도 키 하나에 `CANCELLER_ROLE`만 주는 방안을 검토했다. 취소는 즉시, 예약은 7일이라 Safe가 통째로 털려도 공격자 예약을 계속 무력화할 수 있다. **기각 이유** — ① 서로 다른 기기의 키 2개가 동시에 털리는 시점이면 이미 다른 것도 무너져 있다 ② 그 키가 털리면 **정상 운영도 영구히 막히는 대칭 위험**이 생긴다(D-007과 같은 형태의 동결) ③ 관리 키가 하나 늘고 배포 단계가 복잡해진다. **다시 꺼내지 말 것 — 배포 전에만 넣을 수 있으므로 재론의 실익도 없다.**

**비용** — Safe 배포 가스(Base에서 몇 센트). 하드웨어 지갑 불필요.

**운영 부담이 작다** — Safe가 쓰이는 건 타임락 예약·실행뿐이고 분기 1회 수준이다. **배포 스크립트는 Safe 주소를 생성자 인자로 받기만 하므로 서명 로직이 필요 없다.**

**주간 기록 해시는 Safe로 하지 않는다.** 매주 Safe를 꺼내는 운영은 지속되지 않는다. 가스비만 든 소액 핫월렛을 따로 쓰고 그 주소도 공개한다. (D-009 판정 근거라 어차피 공개돼야 한다)
```

## 2. `docs/DECISIONS.md` — D-007에 「알아야 할 것」 절 추가

D-007 본문 끝에 붙이세요. **제목의 3% 주석은 이미 되어 있으니 건드리지 마세요.**

````markdown
**⚠️ 알아야 할 것 — 운영 키를 EOA 하나가 쥐면 영구 동결 위험**

OZ `TimelockController` 생성자는 proposer에게 `CANCELLER_ROLE`을 **함께** 부여한다.

```solidity
for (uint256 i = 0; i < proposers.length; ++i) {
    _grantRole(PROPOSER_ROLE, proposers[i]);
    _grantRole(CANCELLER_ROLE, proposers[i]);   // ← 같이 부여됨
}
```

운영 키가 유출되면:

```
공격자: 자산 인출 예약 (7일 대기)
나:     즉시 취소
공격자: 재예약  →  나: 재취소  →  무한 반복
```

**공격자는 못 가져간다. 그런데 나도 못 옮긴다.** 안전한 곳으로 빼려면 예약 후 7일을 기다려야 하는데 **취소는 즉시**라 canceller가 항상 이긴다. 결과는 도난이 아니라 **영구 동결**이다.

**D-019(Safe)가 이 문제를 해결한다** — 유출된 키 하나는 서명자 1명일 뿐이라 예약도 취소도 못 한다.

**⚠️ 그리고 7일의 정확한 보장을 다시 확인할 것**

`updateDelay`는 타임락 자신만 호출할 수 있으므로 지연을 0으로 만드는 데도 7일이 든다. 즉 보장은 **"언제나 7일"이 아니라 "어떤 변화도 최소 한 번은 7일 전에 공개된다"**이다.

한 번 7일을 들여 지연을 0으로 만들면 그 뒤로는 대기가 없다. 다만 **한 번 털어가는 데 걸리는 시간은 어느 쪽이든 7일**이므로(바로 예약 7일 vs 지연 낮추기 7일 + 즉시), 지연 낮추기가 유리한 건 몇 년에 걸쳐 반복 인출할 때뿐이다.

**진짜 우회는 설정 실수다** — 생성자에 admin 주소를 넣고 포기하지 않으면 그 주소는 대기 없이 역할을 바꿀 수 있다. 우리는 **처음부터 `admin = address(0)`**이라 그런 주소가 존재하지 않고, `test_NoExternalAdmin`이 이를 고정한다.

**타임락 지연과 달리 완전히 불변인 것** — 베스팅의 `start`/`duration`/`cliff`, 토큰 총량, `mint` 부재, `owner` 부재. 바꾸는 함수가 아예 없다.

> **7일은 자물쇠가 아니라 경보기다.** 못 열게 막는 게 아니라 열리기 전에 반드시 소리가 나게 하는 장치다.
````

## 3. `script/Deploy.s.sol` — 코드 수정

### 3-1. `OPERATOR_ADDRESS` → `SAFE_ADDRESS`, **폴백 제거**

현재 이렇습니다:

```solidity
address operator = vm.envOr("OPERATOR_ADDRESS", deployer);
```

**이게 지금 가장 위험한 한 줄입니다.** 환경변수를 안 채우면 배포 지갑이 조용히 proposer + canceller가 되어 **D-007이 경고한 영구 동결 구조 그대로 메인넷에 올라갑니다.** 폴백을 없애세요.

```solidity
// 타임락에 예약을 걸 수 있는 주소 = Safe 2-of-3 (D-019)
// envAddress는 미설정 시 revert합니다. 폴백을 두지 않는 것이 요점입니다 —
// 배포 지갑이 조용히 proposer가 되면 D-007의 영구 동결 구조가 됩니다.
address safe = vm.envAddress("SAFE_ADDRESS");

require(safe != deployer, "SAFE_ADDRESS == deployer");
require(safe.code.length > 0, "SAFE_ADDRESS is not a contract");
```

`safe.code.length > 0`은 **테스트넷에서도 Safe를 실제로 만들어 예행연습하게 강제**하는 장치입니다. 편의를 위해 EOA를 넣는 순간 메인넷 리허설이 사라집니다. 완화하지 마세요.

이후 `operator` 변수명을 전부 `safe`로 바꾸고, 콘솔 출력도 고치세요:

```solidity
console2.log("safe (proposer):", safe);
```

기존의 `if (operator == deployer) { console2.log("! OPERATOR_ADDRESS 미설정 ...") }` 블록은 **통째로 삭제**합니다. 이제 revert가 대신합니다.

```solidity
 * @notice proposer가 배포 지갑이면 안 됩니다.
```

```
5. 물량 이체 (20M / 65M / 10M)
   ─ 1~5는 한 broadcast ─
6. LP 5구간 생성 (4M)       배포 지갑에서
7. LP 포지션 NFT → 타임락
8. 남은 1M → Safe
9. 배포 지갑 잔고 0 확인
```

**0번이 1번보다 먼저여야 합니다.** Safe 주소가 타임락 생성자 인자입니다. 순서를 틀리면 재배포해야 하고, 그러면 이름·심볼을 태웁니다.

타임락 구성 — `proposers` = [**Safe 2-of-3**], `executors` = [`address(0)`], `admin` = `address(0)`.
실행을 열어둔 것은 키 분실 시 물량이 영구히 잠기는 것을 막기 위해서이고, 예약은 여전히 Safe만 할 수 있으므로 7일 지연은 그대로 강제됩니다.

### 6-2. 「Safe 2-of-3 만들기」 절 신규 (배포 순서 바로 뒤)

````markdown

**Safe는 지갑이 아니라 컨트랙트입니다.** 키를 보관하지 않고 **주소 목록과 정족수**만 저장합니다.

| ② | 폰 지갑 앱 | **반드시 다른 기기** |

```
①번 지갑으로 접속 → 트랜잭션 제안 + 서명   (1/2)

```

두 번째 서명이 들어가는 순간 실행됩니다. 별도 실행 버튼이 없습니다.
③번은 ①이나 ②를 잃거나 털렸을 때만 꺼냅니다.

### ⚠️ 주의

- **③번 키를 편하다고 PC나 클라우드에 두지 마세요.** 그 순간 2-of-3이 사실상 1-of-1이 됩니다
````

### 6-3. 「키 관리」 절 신규

````markdown
### 키 관리

Foundry 공식 권고를 따릅니다 — **테스트넷은 암호화 키스토어, 메인넷은 하드웨어(권장).**

**하드웨어 지갑은 「권장」이지 「필수」가 아닙니다.** Safe 2-of-3이 들어가면 단일 키 유출 손실이 0이 되므로 한계 효용이 낮습니다. 유일하게 남는 단일 키 구간은 아래 **배포 순간**이고, 그것도 일회용 새 키로 상당 부분 완화됩니다. 하드웨어는 **"내 컴퓨터가 이미 감염됐을 수도 있다"에 대한 보험**으로 평가하면 됩니다.

**⚠️ 가장 위험한 시간 — 배포하는 몇 분**

`forge script --broadcast`는 트랜잭션을 **순차 전송**하므로, 토큰 배포 직후 ~ 이체 완료 전까지 **배포 지갑에 1억 개 전량이 있는 순간이 실재합니다.**

> **완화책: 배포 키를 그 배포만을 위해 새로 만들고, 끝나면 비우고 폐기합니다.**

**⚠️ Windows 주의** — WSL2는 USB를 기본 지원하지 않아 하드웨어 지갑이 안 잡힙니다(`usbipd-win` 필요). 하드웨어를 쓸 거면 네이티브 Windows가 편합니다. `--ledger` 실패 사례가 Foundry 이슈로 다수 보고돼 있으니 **반드시 테스트넷에서 먼저 성공시키세요.**

### 지갑을 용도별로 나눕니다

| 용도 | 지갑 | 빈도 |

| 배포·LP 설치 | 배포 지갑 (일회용, 끝나면 비움) | 1회 |
| 타임락 예약·실행 | **Safe 2-of-3** | 분기 1회 |
| 근거리 재고 1M 보관 | **Safe 2-of-3** | 필요시 |
| **주간 기록 해시** | **소액 핫월렛** | **매주** |

주간 해시는 가스비만 필요하고 털려도 잃을 게 없습니다. 매주 Safe를 꺼내는 건 지속되지 않으므로 별도 소액 지갑을 씁니다. **그 주소도 `WALLETS.md`에 공개합니다** — 종료 조건 판정 근거라 어차피 공개돼야 합니다.

⚠️ **근거리 재고 1M을 Safe에 두는 것은 「잠금」이 아닙니다.** Safe는 서명 2개면 즉시 움직이고 타임락을 거치지 않습니다. **「예고 없이 움직일 수 있는 양 1%」는 그대로입니다.** 문서에 이 1M이 7일 예약 대상인 것처럼 쓰지 마세요. (D-014)
````
