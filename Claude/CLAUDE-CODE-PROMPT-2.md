## 0. 무엇을 바꾸는가

배포 전이라 지금만 바꿀 수 있습니다. `start`/`duration`/`cliff`는 **배포하면 변경 함수가 없습니다.**

| | 현재 | 변경 후 |
|---|---|---|
| 창업자 20M — 클리프 | 180일 (6개월) | **90일 (3개월)** |
| 창업자 20M — 기간 | 730일 (24개월) | **365일 (12개월)** |
| 장기 재고 65M — 시작 | 배포 +730일 (2년) | **배포 +365일 (1년)** |
| 장기 재고 65M — 기간 | 2920일 (8년) | **1095일 (3년)** |
| **전체 해제 완료** | **배포 +10년** | **배포 +4년** |

**바뀌지 않는 것 두 가지 — 문구를 고치지 마세요.**

- **「예고 없이 움직일 수 있는 양 = 1%」는 그대로입니다.** 해제분이 지갑이 아니라 타임락으로 가므로(D-015), 일정 단축은 **7일 예고 후** 칸만 키웁니다.
- **클리프 직후 한 번에 열리는 양도 그대로 4,931,506개(약 4.9%)입니다.** 180/730과 90/365가 같은 비율이기 때문입니다. 우연이지만 사실이므로 그대로 씁니다.

**두 일정이 정확히 맞물립니다** — 창업자 베스팅이 끝나는 1년 시점에 장기 재고가 시작합니다. 기존 설계(2년/2년)의 맞물림을 그대로 유지한 것입니다.

## 3. `docs/DECISIONS.md`

### 3-1. D-008 본문 교체

```markdown
## D-008 · 장기 재고는 클리프 대신 미래 시작

**결정** — 장기 재고 65,000,000은 `VestingWallet`에 넣되 **`start`를 배포 +1년, `duration`을 3년**으로 한다. `VestingWalletCliff`를 쓰지 않는다.

> **개정 (D-020)** — 원안은 `start` 배포 +2년, `duration` 8년(완료 10년)이었다. 배포 전에 +1년 / 3년(완료 4년)으로 단축했다. 사유는 D-020.

**이유** — OpenZeppelin은 선형 계산의 기준점이 클리프가 아니라 `start`다. "1년 클리프 + 3년 선형"으로 걸면 1년째에 **21,666,666개(총량 21.7%)가 한 번에 열린다.** 기간을 줄일수록 이 계단이 커지므로, 단축한 지금 이 결정은 원안 때보다 더 중요해졌다.

시작 시각을 미루면 시작 전 해제량이 0이고 시작 후 0부터 선형으로 늘어난다. **한 번에 열리는 지점이 없다.**

**알아야 할 것** — `start`와 `duration`은 생성자에서 정해지고 변경 함수가 없다. **배포하면 못 바꾼다.** 앞당기는 것도 미루는 것도 불가능하다.

**해제 속도가 배포 한도를 뜻하지 않는다.** 실제로 한 회차에 얼마를 풀 수 있는지는 여전히 **풀 깊이의 8%**가 정한다(D-006). 재고가 빨리 풀린다고 빨리 팔 수 있는 것이 아니라, **팔 수 있게 되기까지의 대기가 짧아질 뿐**이다.
```

### 3-2. D-003 제목·본문 수정

- 제목 `## D-003 · 창업자 물량 20%, 6개월 클리프 + 24개월 베스팅` → **`3개월 클리프 + 12개월 베스팅`**
- 「알아야 할 것」의 `클리프 직후 6개월치(약 4.9%)` → **`클리프 직후 3개월치(약 4.9%)`**
  **숫자 4.9%는 그대로입니다.** 20,000,000 × 90 / 365 = 4,931,506으로 개정 전과 같습니다.
- 원안 표기 각주 추가:

```markdown
> **개정 (D-020)** — 원안은 6개월 클리프 + 24개월이었다. 클리프 직후 열리는 양(약 4.9%)은
> 비율이 같아 변하지 않았고, 완료 시점만 2년에서 1년으로 당겨졌다.
```

### 3-3. D-020 신규 (맨 위)

```markdown
## D-020 · 베스팅 일정을 배포 전에 단축한다

**결정** — 창업자 20M을 **3개월 클리프 + 12개월**로, 장기 재고 65M을 **배포 +1년 시작 · 3년 배분**으로 바꾼다. 전체 해제 완료가 배포 +10년에서 **+4년**이 된다.

**이유 ① 8주짜리 약속에 10년짜리 일정은 앞뒤가 안 맞는다.** 이 프로젝트의 유일한 약속은 「멈추지 않는 것」이고 종료 판정은 8주다(D-009). 8주 안에 끝날 수도 있는 프로젝트가 10년 일정을 내걸면, 그 일정은 지킬 각오가 아니라 장식으로 읽힌다.

**이유 ② 재고를 못 쓰는 2년이 실질적 제약이었다.** 초기 LP 4M이 소진되면 다음 구간의 재원은 근거리 잔여 1M과 운영·예비 10M뿐이고, 장기 재고 65M은 2년간 손댈 수 없었다(D-016). 시작을 1년으로 당기면 이 공백이 절반이 된다.

**이유 ③ 예고 없이 움직일 수 있는 양은 변하지 않는다.** 해제분이 지갑이 아니라 타임락으로 가므로(D-015), 일정 단축이 키우는 것은 **7일 예고 후** 칸뿐이다. 공개 문구 「예고 없이 1%」는 그대로다.

**대가 — 정직하게 적는다.**

| | |
|---|---|
| 연간 해제 속도 | 8.1M/년 → **21.7M/년** (총량의 21.7%) |
| 4년 시점 미해제 물량 | 약 40M → **0** |
| 창업자 물량 완료 | 2년 → **1년** |

창업자 20%가 1년에 전부 해제되는 것은 **업계 관행(통상 1년 클리프 + 3~4년)보다 짧고, 이 설계에서 가장 방어하기 어려운 항목이다.** 완화 요인은 수령 주소가 타임락이라 해제돼도 예고 없이는 못 움직인다는 것뿐이고, 그것이 전부다. 숨기지 말고 이 문단째로 공개한다.

**이 방향의 변경은 이번이 마지막이다.** D-013은 공개한 제약을 **조이는 방향으로만** 바꾸도록 한다. 이 단축은 **아직 아무것도 공개·배포되지 않은 시점**이라 가능했다. 첫 기록을 발행한 뒤에는 같은 변경이 규칙 위반이고, 배포한 뒤에는 코드에 변경 함수가 없어 아예 불가능하다.

**기각한 것 — 더 짧게.** 재고 2년 배분(완료 3년)도 검토했다. 연 32.5M(32.5%)은 그 자체로 오버행이 되고, 재고를 쓸 수 있는 것과 별개로 「4년이면 전부 나온다」가 「3년이면 전부 나온다」로 바뀌는 이득이 없다. 기각.
```

계산 근거(문서에는 넣지 말고 검산용으로만):

```
7일 예고 후 = 운영 10M + LP 포지션 4M + 창업자 해제분 + 재고 해제분
못 움직임   = 100M − 1M − 위
창업자 해제분 = 0 (t<90일) / 20M × min(t,365일) ÷ 365일
재고 해제분   = 0 (t<365일) / 65M × min(t−365일,1095일) ÷ 1095일
각 행의 세 칸 합이 반드시 100M이어야 합니다.
```
