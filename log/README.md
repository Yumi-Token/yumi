# 주간 기록

> **이 설계에서 유일하게 실패할 수 있는 방법은 기록을 멈추는 것입니다.**

## 규칙

1. **매주 한 편.** 예외 없이.
2. **못 한 주에는 "못 했다"를 기록합니다.** 건너뛰지 않습니다.
   빈 주가 있는 기록이 끊긴 기록보다 훨씬 강합니다.
3. **실패를 성공보다 먼저 씁니다.** 잃은 돈, 틀린 판단, 안 된 시도.
   성공담은 지어낼 수 있지만 구체적인 실패는 실제로 겪어야만 씁니다.
4. **분량은 작아도 됩니다.** 세 문단이어도 괜찮습니다. 완벽한 글보다 끊기지 않는 글.
5. **남이 확인할 수 있는 항목이 최소 하나 들어갑니다.** ← 가장 중요합니다.

## 기록인가, 일기인가

기준은 분량도 성실함도 아니고 **검증 가능성**입니다.

| 항목 | 확인 방법 |
|---|---|
| 만든 것 | 커밋 해시, PR 번호 |
| 배포·전송 | 트랜잭션 해시 |
| 안 된 것 | 실패한 트랜잭션, 에러 메시지, 날린 금액 |
| 정한 것 | `DECISIONS.md` 항목 번호 |
| 본 것 (부검) | 대상의 주소·마지막 커밋일·출처 링크 |
| 숫자 | 풀 깊이, 보유자 수, 테스트 개수, 가스비 |

**아무것도 못 한 주에는 0이 검증 가능한 숫자입니다.** "이번 주 커밋 0건, 트랜잭션 0건.
회사 일이 몰려서 못 했다" — GitHub을 보면 정말 0인 게 확인되므로 유효한 기록입니다.

감정을 빼라는 뜻이 아닙니다. **감정은 사실에 붙는 각주지 본문이 아닙니다.**

**불통과** — "이번 주는 힘들었다. 그래도 포기하지 않으려 한다."

**통과** — "배포가 세 번 실패했다. 마지막 실패 트랜잭션은 [링크]고 날린 가스비는 0.0004 ETH다.
원인은 RPC 주소를 메인넷으로 잘못 넣은 것이었다. 두 번째 실패 뒤에 노트북을 덮었다."

## 종료 조건

**8주 연속 검증 가능한 기록이 없으면 종료입니다.** 예외 없습니다.

쉬어야 하면 "몇 주 쉽니다, 이유는 이겁니다"라고 쓰면 되고, 그 글도 기록이므로
시계가 다시 흐릅니다. 판정은 아래 온체인 해시로 하며, **줄이는 것만 가능하고
늘리지 않습니다.**

## AI를 어디까지 쓰는가

밝히고 갑니다.

- **AI가 초안** — 「한 것」의 사실 정리, 번역, 톤 검사
- **사람이** — 「안 된 것」, **부검 글의 사실 확인**, 그리고 **발행**

이 구분이 바뀌면 공지합니다.

### 부검 글은 사람이 사실 확인합니다

날짜·주소·링크가 하나라도 틀리면, 검증 가능성을 파는 프로젝트가 검증 불가능한 글을 낸 것이 됩니다.
AI가 조사를 돕더라도 **발행 전에 사람이 원본에서 직접 확인**합니다.

그리고 부검 글에는 **토큰 관련 요소를 넣지 않습니다.** 가격, 구매 링크, 심볼, 풀 정보,
"저는 멈추지 않습니다" 같은 대비 문구 전부입니다.

이유는 두 가지입니다. 하나는 자기 상품 광고로 읽히면 글의 신뢰가 사라지기 때문이고,
다른 하나는 남을 관측하는 글에 자기 판매를 섞는 것이 톤 표의 모든 항목과 충돌하기 때문입니다.

**관측만 씁니다.** "마지막 커밋은 2024-03-11이고 그 뒤 트랜잭션은 없습니다"는 관측입니다.
"유동성이 이 정도밖에 안 되는 프로젝트였습니다"는 평가입니다. 후자는 쓰지 않습니다.
판단은 읽는 사람이 합니다.

### 지시문 원본은 공개하지 않습니다

AI에게 준 작업 지시문은 저장소에 올리지 않습니다 (`Claude/` 폴더, `.gitignore` 처리).
**결정과 그 근거는 [`docs/DECISIONS.md`](../docs/DECISIONS.md)에 전부 옮겨져 있고,
지시문에만 있는 것은 초안과 중간 계산입니다.**

프롬프트는 산출물이 아니라 도구라서 그렇습니다. 공개하면 매주 그것도 정리해야 하고,
**부담이 늘면 기록이 밀립니다.** 밝히고 갑니다.

## 파일 이름

```
log/2026-W35.md
```

ISO 주차를 씁니다. 순서가 자동으로 맞고 빠진 주가 눈에 보입니다.

## 톤

| 쓰지 않을 말 | 쓸 말 |
|---|---|
| 혁신, 게임체인저, 패러다임 | 이번 주에 한 것 / 안 된 것 |
| 커뮤니티 여러분과 함께 | 이렇게 정했고, 이유는 |
| 곧 큰 소식이 있습니다 | 모르겠습니다 |
| 날짜가 박힌 로드맵 | 틀렸습니다. 고치겠습니다 |
| 느낌표·이모지 남발 | 구체적인 숫자와 주소 |

**기준 하나: 6개월 뒤에 읽었을 때 부끄럽지 않을 문장만 씁니다.**

## 온체인 해시 남기기 (선택, 나중에)

글을 발행할 때 그 글의 해시를 Base에 트랜잭션 하나로 남기면
기록이 소급 수정될 수 없고, 지속 자체가 온체인에서 보입니다.
가스비는 1원 남짓입니다.

```bash
# 예시 — 글 파일의 해시를 자기 자신에게 보내며 데이터로 첨부
cast send $MY_ADDRESS \
  --value 0 \
  --data $(cast keccak "$(cat log/2026-W35.md)") \
  --rpc-url base \
  --private-key $PRIVATE_KEY
```

지금 당장은 필요 없습니다. **먼저 몇 편을 쓰고, 끊기지 않는다는 게 확인되면** 붙이세요.
