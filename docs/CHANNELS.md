## 1-2. 소개란 — 126자 (제한 150자)

```
유미(YUMI)는 제 고양이입니다.
저한테 뭘 해주겠다고 한 적이 없습니다. 있는 것만으로 위안이 됩니다.

이 코인도 아무것도 약속하지 않습니다.
다만 매주 기록을 남기고, 그 기록이 우리의 기억 속에 위안이 되길 바랍니다.
```

> **「다만」이 논리를 지탱합니다.** 「아무것도 약속하지 않는다」 뒤에 「매주 기록한다」가
> 그냥 오면 모순으로 읽힙니다 — 그것도 약속이니까요. 「다만」이 그것을 **유일한 예외**로
> 표시하고, 그게 이 프로젝트의 구조 그대로입니다.
>
> **종료 조건은 소개란에 넣지 않습니다.** 고정 게시물 첫 줄에 이미 있습니다.
> 소개는 「누구인지」, 게시물은 「무슨 일이 있었는지」로 나눕니다.

# 2. 디스코드

## 2-0. 디스코드 봇으로 설정하기

디스코드 서버 초기 설정은 **스크립트로 했습니다** — 채널·권한·고정 메시지·자동조정을
한 번에 만들고, 여러 번 돌려도 이미 있는 것은 건너뜁니다.

**그 스크립트는 저장소에 두지 않습니다.** 홀더·검증과 무관하고 서버 구조만 노출하기
때문입니다. (D-032) **무엇을 만들었는지는 아래에 전부 적어뒀습니다** — 문안도, 권한도,
자동조정 규칙도 여기 있으므로 손으로도 같은 서버를 만들 수 있습니다.

**① 봇 만들기**

1. https://discord.com/developers/applications → **New Application** → 이름 `유미 기록`
2. 좌측 **Bot** → **Reset Token** → 토큰 복사
3. 좌측 **OAuth2** → **URL Generator**
   - Scopes: `bot`
   - Permissions: `Manage Channels`, `Manage Messages`, `Send Messages`, `Manage Server`
4. 생성된 URL 로 접속해 **내 서버에 봇 초대**

**② `.env` 에 두 값 넣기**

```
DISCORD_BOT_TOKEN=복사한_토큰
DISCORD_GUILD_ID=서버_ID
```

서버 ID는 디스코드 **설정 → 고급 → 개발자 모드**를 켜고 서버 이름 우클릭 → **서버 ID 복사**.

> 🔴 **봇 토큰은 서버를 조작할 수 있는 열쇠입니다. 개인키처럼 다루세요.**
> `.env`는 `.gitignore`에 있어 커밋되지 않습니다. 유출되면 즉시 재발급하세요.

**③ 미리보기 → 적용**

스크립트는 인자 없이 돌리면 **무엇을 할지 보여주기만** 하고, `--apply`를 붙여야
실제로 바꿉니다. 여러 번 돌려도 안전하고, 이미 있는 것은 건너뜁니다.
토큰은 `.env`에서만 읽고 인자로 받지 않습니다.

**④ 스크립트가 못 하는 것 — 손으로**

| | 어디서 |
|---|---|
| 서버 아이콘 | 서버 설정 → `assets/yumi-logo-256.png` |
| ~~규칙 동의 화면~~ | ✅ 켜져 있습니다 (2-0-5) |
| **DM 스팸 필터 최고** · **습격 보호** | 서버 설정 → 안전 설정 |
| **초대 링크** | ⚠️ **저장소를 Public 으로 바꾼 뒤에** 만드세요 |

켜면 디스코드 커뮤니티 가이드라인 준수에 동의하는 것이 됩니다. 되돌릴 수 있습니다.

**켜져 있습니다.** `MEMBER_VERIFICATION_GATE_ENABLED`.
**봇 차단에 실제로 기여하는 것은 이것입니다** — 사기 봇 상당수가 여기서 걸립니다.

```
1. 가격·수익 얘기는 하지 않습니다. 정해진 사실만 얘기합니다
2. 공식 주소는 저장소 한 곳에만 있습니다. DM으로 받은 주소는 전부 사칭입니다
3. 개인키·시드 문구를 묻는 사람은 전부 사기입니다
4. EN — No price or returns talk. Only what is already settled gets stated.
5. EN — The official address lives only in the repository. Any address sent by DM is a scam.
6. EN — Anyone asking for your private key or seed phrase is a scammer.
```

⚠️ **한 항목 안에서 줄바꿈이 안 됩니다.** 디스코드가 제거합니다.
한글과 영문을 한 줄에 넣으면 붙어버려서 읽을 수 없게 됩니다.
그래서 **여섯 항목으로 나눴습니다.** 한글 셋, 영문 셋.

**1번 뒤쪽 절반이 중요합니다.** 앞쪽만 있으면 「정해지고도 안 알리는 것」이
규칙이 되어 버립니다. 그건 다른 종류의 거짓말입니다.
`CLAUDE.md` 의 확정 사실 / 약속 구분과 같은 선이고,
`#시작하기` 고정 메시지 3번(과 영문본)에도 같은 문장이 들어가 있습니다.
**한쪽만 고치면 어긋납니다.**

「습격 보호」도 같은 안전 설정 안에 있습니다. 함께 켜세요.

## 2-0-1. 채널을 늘리지 않는 이유

전형적인 코인 디스코드는 채널이 15개고 대부분 죽어 있습니다.
그 구성은 **가격을 기대하고 온 사람을 위한 것**이고, 우리가 줄 수 있는 것은 기록입니다.

그리고 **멤버가 적은데 채널이 많으면 죽은 프로젝트로 보입니다.**
관리 부담이 늘면 주간 기록을 밀어내고, 그게 종료 조건과 충돌합니다.
(`docs/UTILITY.md` 조건 ③과 같은 논리)

**「그럴듯함」은 채널 수가 아니라 완성도에서 옵니다** — 아이콘, 규칙 동의,
채널 설명, 작동하는 자동조정.

## 2-0-2. 역할

역할은 **둘뿐이고 목적은 사칭 방지**입니다. 설정 스크립트가 만듭니다 (2-0 참조).

| 역할 | 권한 | 멤버 |
|---|---|---|
| `@발행자` | 관리자 | 발행자 한 명 |
| `@운영진` | 메시지 관리 · 스레드 관리 · 타임아웃 | 지금은 0명 |

**둘 다 멤버 목록 상단에 따로 표시되고, 멘션은 막아뒀습니다.**
누가 DM으로 「운영자입니다」라고 해도 목록에 역할이 없으면 바로 들통납니다.
「공식 주소는 저장소 한 곳에만」과 같은 원리입니다.

`@운영진` 에 **추방·차단은 넣지 않았습니다.** 되돌리기 어려운 것은 발행자가 합니다.
지금 0명인데 미리 만들어 둔 것은, 급할 때 만들면 권한 설계를 대충 하게 되기 때문입니다.

**보유량 등급(🐋/🦐 류)은 만들지 않습니다.** 이유는 D-028 에 있습니다.
요약하면 — `#잡담` 에 지갑 주소를 못 쓰게 막아놓고 멤버 목록에 잔액 등급을 띄우면
**누가 큰 홀더인지 공개하는 셈**이고, 그 사람이 사칭 DM의 표적이 됩니다.

## 2-0-3. 보안 설정

설정 스크립트가 세 가지를 맞춥니다.

| 설정 | 값 | 왜 |
|---|---|---|
| 인증 수준 | **높음** | 서버 가입 후 10분이 지나야 글을 쓸 수 있습니다. 사기 봇은 대부분 막 만든 계정이라 이것만으로 상당수가 걸러집니다. 「매우 높음」(전화 인증)은 정상 이용자도 많이 막혀 쓰지 않습니다 |
| 미디어 검사 | **모든 멤버** | 역할이 있다고 봐주지 않습니다 |
| 기본 알림 | **멘션만** | 기본값(모든 메시지)이면 알림 때문에 사람들이 나갑니다 |

### 🔴 API 로 안 되는 것 — 손으로 하셔야 합니다

| | 왜 API 로 안 되나 |
|---|---|
| **2단계 인증 요구** | **서버 소유자만** 바꿀 수 있습니다. 봇은 관리자여도 불가능합니다 |
| 서버 아이콘 · DM 스팸 필터 · 습격 보호 | 봇 권한 밖입니다 |
| 기본 채널 삭제 | **되돌릴 수 없어서 일부러 스크립트에 넣지 않았습니다** |

> 커뮤니티 활성화와 규칙 동의 화면은 **API 로 됩니다.** 처음에 안 되는 줄 알고
> 이 표에 넣어뒀는데, 실제로 해보니 됐습니다. 둘 다 지금 켜져 있습니다 (2-0-4 · 2-0-5).

**2단계 인증 요구가 이 중 가장 중요합니다.** 켜두면 관리 권한을 가진 계정이
탈취돼도 채널 삭제·차단 같은 되돌릴 수 없는 행동을 바로 하지 못합니다.
서버 설정 → 안전 설정 → 「2단계 인증 요구」. **발행자 계정에 2FA 가 먼저 켜져 있어야 합니다.**

🔴 **순서를 바꾸면 이 스크립트가 깨집니다** — 서버에 2FA 를 요구하면 봇의 관리 작업도
봇 소유자 계정의 2FA 를 확인하기 때문입니다. 설정 경로와 백업 코드 보관은
[`SECURITY.md`](SECURITY.md) 「계정 2단계 인증」에 있습니다.

## 2-2. `#시작하기` — 3개 메시지

⚠️ **디스코드는 메시지당 2000자입니다.** 셋으로 나눠 연속으로 올리고 **전부 고정**하세요.

### 메시지 1 — 여기가 무엇인지

```
# 여기가 무엇인지

1인이 코인 하나를 만들어가는 과정을 **매주 공개 기록**으로 남기는 곳입니다.
기록이 주(主)이고 토큰은 종(從)입니다. 기록은 무료이고, 토큰이 없어도 전부 볼 수 있습니다.

**약속은 하나뿐입니다 — 멈추지 않는 것.**

8주 연속 확인 가능한 기록이 없으면 종료합니다. 예외 조항은 없습니다.
판정은 제가 하지 않습니다. 매주 기록의 해시를 체인에 남기고,
마지막 트랜잭션이 8주 이상 전이면 누가 봐도 종료입니다.

**7일은 자물쇠가 아니라 경보기입니다.** 못 열게 막는 게 아니라
열리기 전에 반드시 소리가 나게 하는 장치입니다.
```

### 메시지 2 — 먼저 읽어주세요

```
## ⚠️ 먼저 읽어주세요

**1) 메인넷 토큰은 아직 없습니다.**
지금 있는 것은 **테스트넷(Base Sepolia) 컨트랙트뿐**이고 아무 가치가 없습니다.
주소는 전부 공개돼 있습니다 → https://github.com/Yumi-Token/yumi/blob/main/docs/WALLETS.md

어디선가 「유미 코인」이라며 주소를 건네는 사람이 있다면 **전부 사칭입니다.**
메인넷에 올리면 여기와 저장소에 동시에 올립니다. 그 전에는 어떤 주소도 공식이 아닙니다.

**2) 심볼은 신원이 아닙니다. 주소가 신원입니다.**
`YUMI`라는 심볼은 이미 다른 체인에 여러 개 있습니다. 누구나 같은 심볼로
토큰을 만들 수 있고, 등록소 같은 건 존재하지 않습니다.
**공식 주소는 저장소 한 곳에만 올립니다.** DM·검색 결과·다른 사이트에서 받은 주소는 믿지 마세요.

**3) 사전 판매를 하지 않습니다.**
개별 판매 요청은 받지 않습니다. **예외 없습니다.**
사고 싶은데 방법을 모르시겠다면 **방법은 얼마든지 도와드립니다.**
다만 제가 돈을 받고 토큰을 보내드리는 일은 하지 않습니다.

**4) 제가 여러분의 지갑에 접근할 일은 절대 없습니다.**
시드 문구·개인키·비밀번호를 묻는 사람은 **전부 사기입니다. 저를 사칭해도 마찬가지입니다.**
```

### 메시지 3 — 규칙과 링크

```
## 이 채널에서 하지 않는 것

· **가격 얘기** — 얼마까지 오를지, 언제 사야 할지는 여기서 다루지 않습니다
· **수익 약속** — 수익률·원금·「N배」 같은 말은 쓰지 않습니다
· **날짜가 박힌 로드맵** — 지키지 못한 계획은 나중에 불리한 기록이 됩니다
· **정해지지 않은 것을 정해진 것처럼 말하는 것** — 무엇에 대해서든

가격 얘기를 하시는 분을 막지는 않지만 **제가 답하지는 않습니다.**
그리고 수익을 약속하는 글은 지웁니다 — 제가 쓴 게 아니어도요.

## 대신 여기서 하는 것

· 이번 주에 **뭘 했고 뭐가 안 됐는지**
· 틀린 계산, 잘못 쓴 문서, 되돌린 결정
· 숫자와 주소 — **누구나 직접 확인할 수 있는 것들**

**실패 기록이 이 프로젝트에서 가장 값진 콘텐츠입니다.**
성공담은 지어낼 수 있지만 구체적인 실패는 겪어야만 씁니다.

## 제가 가진 물량과 움직일 수 있는 범위

숨기지 않습니다. 전부 문서에 있습니다.

· **예고 없이 움직일 수 있는 양은 총량의 1%**이고 시간이 지나도 그대로입니다
· 그 1%가 시장에서 어떤 크기인지는 **직접 계산하실 수 있게** 해뒀습니다 —
  수량(1,000,000)과 초기 유동성 구간표가 전부 공개돼 있습니다.
  제 계산을 믿는 것보다 그쪽이 낫습니다
· 나머지는 전부 **7일 사전 예약**을 거칩니다. 무엇을 하든 7일 전에 보입니다
· 테스트넷에서 이미 확인했습니다 — 베스팅 수령 주소가 타임락인지,
  배포 지갑에 예약 권한이 없는지. 주소로 직접 보실 수 있습니다
```

## 2-2-1. `#시작하기` 영문 병기 — 2개 메시지

**번역이 아니라 같은 내용을 영어로 다시 쓴 것입니다.** 한글본이 원본이고,
둘이 어긋나면 그것도 「공지와 코드가 다른」 상태입니다.

**영어가 봇을 막지는 않습니다.** 막는 것은 자동조정과 인증 수준입니다.
영문본의 목적은 다릅니다 — 영어권 방문자가 **규칙을 못 읽어서 어기는 경우**를 없애고,
**사기 경고를 못 읽는 사람이 없게** 하는 것입니다. 크립토 서버 방문자의 상당수가 영어권입니다.

원본은 이 문서 아래의 문안입니다. 스크립트는 여기서 가져다 씁니다.
한글본을 고치면 **영문본도 같이 고쳐야 합니다.**

| 메시지 | 대응하는 한글본 |
|---|---|
| `# What this is · English` | 메시지 1 + 메시지 3 (합쳤습니다) |
| `## ⚠️ Read this before anything else` | 메시지 2 |

한글은 3개인데 영문은 2개인 이유 — 고정 메시지가 6개가 되면 **아무도 안 읽습니다.**
영어권 방문자에게 가장 중요한 것은 ②의 사기 경고라서 그쪽을 온전히 남기고,
①과 ③을 하나로 합쳤습니다.

```

```

```

첫 기록이 올라가면 여기에 링크와 앵커 트랜잭션이 함께 올라옵니다.

앵커 목록 → https://github.com/Yumi-Token/yumi/blob/main/log/ANCHORS.md
```
