# 기록 앵커링 — 매주 하는 일

종료 조건(D-009)의 판정 기준은 **해시 지갑이 보낸(from) 마지막 기록 해시 트랜잭션의 블록 타임스탬프**입니다. calldata 가 `LOG ` 로 시작하는 것만 셉니다 — 그 주소로 **들어온** 트랜잭션과 `LOG ` 로 시작하지 않는 트랜잭션은 판정에 넣지 않습니다. (D-034)
이 문서는 그 트랜잭션을 만드는 절차입니다.

**커스텀 코드가 없습니다.** 0원짜리 트랜잭션 하나에 해시를 실어 보내는 것이 전부입니다.

---

## 순서 — 반드시 이 순서로

```
1. 기록을 발행한다 (사람이 읽을 수 있는 곳에 올라간다)
2. 발행된 파일의 SHA-256을 구한다
3. 그 해시를 트랜잭션에 실어 보낸다
4. log/ANCHORS.md 에 (파일명, 해시, 트랜잭션) 을 추가한다
```

**⚠️ 2번이 1번보다 먼저면 안 됩니다.** 해시가 가리킬 대상이 아직 공개되지 않았기 때문입니다.

**⚠️ 앵커 트랜잭션 링크를 기록 파일 안에 적지 마세요.** 파일을 고치면 해시가 달라져
방금 올린 앵커가 무효가 됩니다. 그래서 앵커 정보는 `log/ANCHORS.md`라는
**별도 파일**에 모읍니다. 그 파일은 해시 대상이 아닙니다.

**⚠️ 발행한 기록 파일은 이후 수정하지 않습니다.** 고치면 해시가 깨집니다.
이것은 버그가 아니라 **사후 수정을 할 수 없다는 증거**입니다.
정정할 일이 생기면 다음 기록에 「지난번 기록의 이 숫자가 틀렸다」고 씁니다.

---

## 명령

**⚠️ `sha256sum`은 PowerShell에 없습니다.** Git Bash나 WSL에만 있습니다.
Windows PowerShell을 쓴다면 `Get-FileHash`를 쓰세요 — 아래 두 명령의 결과는 같습니다.

```powershell
# 2) 해시 — PowerShell
(Get-FileHash log/2026-W35.md -Algorithm SHA256).Hash.ToLower()
# 64c757...(64자)
```

`.ToLower()`가 필요한 이유는 `Get-FileHash`가 **대문자로** 출력하기 때문입니다.
앵커 문자열은 소문자로 통일합니다 — 대소문자가 섞이면 남이 검증할 때 헷갈립니다.

```bash
# 2) 해시 — Git Bash / WSL
sha256sum log/2026-W35.md
# 64c757...(64자)

# 3) 앵커 — 주간 해시 지갑에서 자기 자신에게 0원 전송, calldata에 해시
cast send <해시지갑 주소> \
  $(cast from-utf8 "LOG 2026-W35.md sha256:a3f2...") \
  --value 0 --account weekly --rpc-url base
```

**형식** — `LOG <파일명> sha256:<64자 16진수>`

### ⚠️ 앵커는 반드시 Base 메인넷에 남깁니다

**테스트넷은 언젠가 종료됩니다.** Base Sepolia가 내려가면 그 위의 트랜잭션도 함께 사라지고,
**종료 조건(D-009)의 판정 근거가 없어집니다.** 「멈추지 않았다」를 증명할 방법이 사라지는 것이라,
이 프로젝트에서는 그게 가장 나쁜 결과입니다.

**토큰이 아직 메인넷에 없어도 상관없습니다.** 앵커는 0원짜리 트랜잭션에 해시만 싣는 것이라
토큰과 무관합니다. 토큰의 메인넷 배포 시점과 앵커 시작 시점은 별개입니다.

**테스트넷 앵커는 리허설이고 판정에 들어가지 않습니다.**
아래 명령의 `--rpc-url base_sepolia`는 연습할 때만 씁니다.

그래서 **해시 지갑에는 Base 메인넷 ETH가 소액 있어야 합니다.**
앵커 1회가 22,000 gas이므로 1년치(52회)도 몇십 원입니다. 0은 아닙니다. (D-018)

UTF-8로 넣기 때문에 **Basescan의 Input Data를 UTF-8로 보면 사람이 그냥 읽습니다.**
디코딩 도구가 필요 없습니다.

**비용** — 21,000 + 계산자료 약 1,400 = **약 22,000 gas.**
테스트넷 리허설 실측이 **24,480 gas**였습니다.
같은 날 배포 전체(트랜잭션 7건)가 **3,545,148 gas**였으니 **앵커 1회는 그 0.7%**입니다.

원화로 적지 않는 이유는 ETH 값에 따라 달라지기 때문입니다.
**gas 수량은 안 변하니 그것만 적습니다.**

**⚠️ 반드시 테스트넷에서 한 번 성공시킨 뒤에 하세요.** `cast`의 raw calldata 전달
방식은 버전에 따라 다를 수 있습니다. 실패하는 절차를 8주 동안 반복할 수는 없습니다.

**PowerShell에서는 `$(...)` 치환이 bash와 다릅니다.** 두 줄로 나누세요.

```powershell
$data = cast from-utf8 "LOG 2026-W35.md sha256:64c757..."
cast send <해시지갑 주소> $data --value 0 --account weekly --rpc-url base
```

**실측 (2026-08-23 테스트넷 리허설)** — 가스 24,480, 소요 시간 3분.
키스토어 등록은 처음 한 번뿐이라 다음 주부터는 2단계입니다.

## 남이 검증하는 방법

```bash
# 파일을 받아서 (PowerShell 은 Get-FileHash)
sha256sum 2026-W35.md

# 트랜잭션의 입력값을 읽어서 (0x 를 떼고 넘겨야 합니다)
cast to-utf8 $(cast tx <TXHASH> input --rpc-url base | sed 's/^0x//')

# 두 해시가 같은지 본다. 시각은 그 트랜잭션의 블록 타임스탬프다.
```

**`log/ANCHORS.md`가 없어도 검증됩니다.** 해시 지갑 주소가 `docs/WALLETS.md`에
공개돼 있으므로, 그 주소의 트랜잭션 목록만 보면 모든 앵커가 시간순으로 나옵니다.
**체인이 원본이고 `ANCHORS.md`는 편의입니다.**

## 규칙

**아무것도 못 한 주에도 합니다.** 「못 했다」도 기록이고(D-009),
「이번 주 커밋 0건」은 확인 가능한 숫자입니다(D-012).
**빈 주가 있는 기록이 끊긴 기록보다 강합니다.**

**타임락을 거치지 않습니다.** 해시 지갑에서 직접 보내는 평범한 트랜잭션이고,
실패할 조건이 없어서 D-024의 「방치된 예약」 문제와 무관합니다.

**해시 지갑을 바꾸면 판정이 끊깁니다.** 바꿀 때는 「이 주소에서 저 주소로 옮겼고
이 트랜잭션이 그 증거」를 기록에 남기고 `docs/WALLETS.md`를 갱신하세요.
(`docs/SECURITY.md` 참조)

**그 지갑에는 가스비만 둡니다.** 털려도 잃을 것이 없어야 매주 편하게 씁니다.

---

## 절차가 10분을 넘으면 잘못된 것입니다

8주 규칙을 지키는 것은 코드가 아니라 **마찰의 크기**입니다.
매주 30분이 걸리는 절차는 3주쯤 지나면 미뤄지기 시작합니다.
오래 걸린다면 절차를 고치세요. 의지로 버티는 것은 8주를 못 갑니다.
