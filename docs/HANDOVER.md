## 지난 회차에 끝낸 것

트레저리 4분할을 `script/Deploy.s.sol`에 반영했습니다. **새 컨트랙트 파일은 만들지 않았습니다.**

| 버킷 | 수량 | 무엇으로 | 잠금 |
|---|---|---|---|
| 창업자 | 20,000,000 | `FounderVesting` (기존) | 6개월 클리프 + 24개월 선형 |
| 장기 재고 | 65,000,000 | `VestingWallet` 직접 `new` | `start` = 배포 +730일, `duration` = 2920일 |
| 운영·예비 | 10,000,000 | `TimelockController` 직접 `new` | `minDelay` = 7일 |
| 근거리 재고 | 5,000,000 | 트레저리에 잔류 | 없음 |

전부 한 broadcast 안에서 끝납니다. 스크립트 마지막에 `require`로
「합 == INITIAL_SUPPLY」와 「트레저리 잔량 == 5,000,000」을 자기 점검합니다.

### 타임락 관리자를 처음부터 만들지 않았습니다

`TimelockController` 생성자의 마지막 인자(`admin`)에 `address(0)`을 넘겼습니다.
나중에 포기하는 대신 처음부터 없앤 것이고, 이유는 D-004와 같습니다 —
"나중에 잠그겠다"는 상태가 존재하면 안 되기 때문입니다.

권한이 사라진 건 아닙니다. 타임락 자신이 관리자이므로 역할 변경도, 지연 시간 변경도
7일 예약을 거쳐 할 수 있습니다. `test_MinDelayCannotBeChangedDirectly`가 이를 고정합니다.

### 새로 생긴 테스트 파일 3개

| 파일 | 고정하는 주장 |
|---|---|
| `test/Inventory.t.sol` | 장기 재고에 **한 번에 열리는 지점이 없다** (D-008) |
| `test/Timelock.t.sol` | 운영 물량은 **7일 예약 없이 안 움직인다** (D-007) |
| `test/Allocation.t.sol` | 배분의 합 == 총량, **예고 없이 움직일 수 있는 양 == 3%** |

`Allocation.t.sol`은 숫자를 `script/Deploy.s.sol`의 `public constant`에서
**직접 읽어옵니다.** 배포 스크립트 상수를 바꾸면 테스트가 깨지고, 그때
`docs/TOKENOMICS.md`도 같이 고쳐야 한다는 신호입니다.
