## 코드로 구현이 끝난 것

새 컨트랙트 파일은 만들지 않았습니다. 장기 재고와 타임락은
OpenZeppelin 구체 클래스를 배포 스크립트에서 그대로 `new` 합니다.

| 버킷 | 수량 | 무엇으로 | 잠금 |
|---|---|---|---|
| 창업자 | 20,000,000 | `FounderVesting` | 6개월 클리프 + 24개월 선형 |
| 장기 재고 | 65,000,000 | `VestingWallet` | `start` = 배포 +730일 / `duration` = 2920일 |
| 운영·예비 | 10,000,000 | `TimelockController` | `minDelay` = 7일 |
| 근거리 재고 | 5,000,000 | 트레저리 잔류 | 없음 |

**두 베스팅의 수령 주소는 타임락입니다.** (D-015) 그래서 배포 순서가
`TimelockController` → `Token` → 베스팅 둘 → 이체 순입니다. 순서를 바꾸지 마세요.

타임락 구성 — `proposers` = [운영자], `executors` = [`address(0)`], `admin` = `address(0)`.
실행을 열어둔 것은 운영자 키 분실 시 물량이 영구히 잠기는 것을 막기 위해서이고,
예약은 여전히 운영자만 할 수 있으므로 7일 지연은 그대로 강제됩니다.

## ⚠️ 풀 생성 전에 반드시 알아야 할 것 넷

**① 목표 가격을 정확히 설정할 수 없습니다.** 틱 스페이싱 때문입니다. 1% 티어(spacing 200) 기준 —

| 목표 | 실제 설정되는 값 | 오차 |
|---|---|---|
| $0.0005 | $0.00049685 | −0.63% |
| $0.005 | $0.00495513 | −0.90% |
| $0.05 | $0.04941768 | −1.17% |

**문서의 $0.0005를 그대로 공지하면 「공지와 코드가 다른」 상태가 됩니다.**
풀 생성 후 **실제 tick에서 역산한 가격**을 공개 숫자로 확정하고 문서를 고치세요.

**② 토큰이 token0일지 token1일지 배포 전에 알 수 없습니다.** 주소 크기로 정해지고 사실상 난수입니다.
방향이 뒤집히면 "현재가 위쪽에 구간을 잡는다"의 부호가 반대가 되고, **틀리면 mint 시 USDC를
요구해서 「내 현금 0」 전제가 깨집니다.**

- TOKEN이 token0 → `현재 tick < tickLower`
- TOKEN이 token1 → `현재 tick > tickUpper`

**③ 풀을 직접 초기화하세요.** `createAndInitializePoolIfNecessary`로 초기화하고 **즉시** mint하지 않으면
제3자가 임의 가격으로 먼저 초기화할 수 있습니다.

**④ Uniswap v3를 쓰세요.** v4에는 `collect()`가 없고 수수료 회수와 원금 회수가 같은
함수(`modifyLiquidities`)를 공유합니다. 그러면 "무엇을 회수했는지"를 함수 이름으로
구별할 수 없어져 검증 가능성이 떨어집니다.

> LP 관련 작업을 타임락으로 예약할 때, **같은 calldata를 두 번 예약하려면 salt를 바꿔야 합니다.**
> `collect()`처럼 인자가 매번 같은 호출에서 반드시 걸립니다.
> `test_SameOperationCannotBeScheduledTwice`가 이 함정을 고정해뒀습니다.
